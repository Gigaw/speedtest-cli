# speedtest-cli

Консольный скрипт, который измеряет скорость скачивания: делает 10 последовательных запросов к указанному адресу, полностью скачивает каждый ответ и выводит среднее время запроса, общий объём и скорость.

## Требования

Python 3.8+. Сторонние зависимости не нужны, используется только стандартная библиотека.

## Запуск

```bash
git clone https://github.com/Gigaw/speedtest-cli.git
cd speedtest-cli
python3 speedtest.py <URL>
```

Пример:

```bash
python3 speedtest.py https://proof.ovh.net/files/10Mb.dat
```

Количество запросов можно изменить флагом `-n` (по умолчанию 10):

```bash
python3 speedtest.py <URL> -n 5
```

### Версия на Node.js

Тот же функционал и тот же формат вывода есть в `speedtest.mjs`. Нужен Node.js 18.13+ (встроенный `fetch`; проверено на Node 22), без зависимостей и без `npm install`:

```bash
node speedtest.mjs <URL>
node speedtest.mjs <URL> -n 5
```

## Единицы

- **Скорость: Мбит/с** (мегабиты в секунду). В этих единицах провайдеры указывают тарифы. В скобках та же скорость в МБ/с.
- **Объём: МБ**, время: секунды.
- Используются десятичные приставки: 1 МБ = 10⁶ байт, 1 Мбит = 10⁶ бит.

## Как считается

- Время запроса: от отправки запроса до получения последнего байта тела ответа.
- Среднее время: сумма времён, делённая на количество запросов.
- Скорость: общий объём скачанных данных, делённый на суммарное время всех запросов.
- Объём считается по фактически полученным байтам, а не по заголовку `Content-Length`.
- Каждый запрос открывает новое соединение (без keep-alive), в обеих версиях одинаково.
- В время входят DNS, установка TCP/TLS-соединения и задержка до первого байта. На маленьких файлах это заметно занижает скорость, поэтому лучше брать файл от нескольких мегабайт.
- Чтобы не получать ответ из кеша, отправляется заголовок `Cache-Control: no-cache`.

## Тест

```bash
python3 -m unittest   # Python
node --test           # Node.js
```

Тест поднимает локальный HTTP-сервер и проверяет, что скрипт скачивает и учитывает все байты всех запросов. Доступ в интернет не нужен.
